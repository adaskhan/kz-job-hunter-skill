# KZ Job Hunter

Поиск работы в Казахстане, СНГ и на международной удалёнке. Сбор вакансий делает скрипт
`scripts/kz_jobs.py` (только stdlib Python), фильтры и предпочтения пользователя хранятся в профиле.

Справочники (читай по необходимости):
- `references/platforms.md` — все источники по группам (Казахстан, СНГ, международная удалёнка, Affiliate/ИИ,
  карьерные страницы, Telegram, LinkedIn): что собирает скрипт, что только через браузер и как именно
- `references/kz-specifics.md` — налоги и «на руки», регионы hh, языки, ИП/ГПХ, частые формулировки в вакансиях

---

## ⚠️ Правила (всегда)

1. **Язык общения** — тот, на котором пишет пользователь (рус/қаз/eng). Сопроводительные — на языке вакансии.
2. **Никаких откликов без явного «да»** в чате на конкретный список. Отклик = сообщение работодателю от имени пользователя.
3. **Пароли, ИИН, номера карт/удостоверений не вводить и не просить в чате.** Логин на площадках пользователь делает сам в браузере.
4. **Зарплата в сопроводительных не упоминается.**
5. **Все ссылки в отчёте кликабельные** `[текст](https://...)` и ведут на конкретную вакансию / пост `https://t.me/канал/ID`. Пост без прямой ссылки в отчёт не попадает.
6. **Фильтры исключения проверяются по полному тексту** (название + описание), не только по названию.
7. **Флаги ≠ отсев.** Казахский язык, английский выше уровня пользователя, тестовое, «только граждане РК» — показываем в отдельной секции, не скрываем.
8. **Одна упавшая площадка не останавливает прогон** — отмечаем в отчёте и идём дальше.

## Хранилище

Папка `~/.kz-job-hunter/` (создать при первом запуске):
- `profile.json` — профиль поиска (схема — `profile.example.json` рядом со скиллом)
- `resume.md` — текст резюме (извлечённый из PDF / профиля hh)
- `seen.json` — id уже показанных вакансий (ведёт скрипт)
- `applied.json` — история откликов: `[{id, url, title, company, date, status}]`
- `runs/ГГГГ-ММ-ДД.json` и `reports/ГГГГ-ММ-ДД.md` — результаты прогонов

## Фаза 1. Онбординг (если нет `~/.kz-job-hunter/profile.json`)

Задай все вопросы одним сообщением:

```
Настроим поиск. Ответьте на всё сразу — я запомню.

1. Кем ищете работу (должность своими словами)?
2. Ключевые слова для поиска (через запятую, рус/англ): ___
3. Город(а): Алматы / Астана / Шымкент / другой / вся РК / только удалёнка
4. Формат: офис / гибрид / удалённо (можно несколько)
5. Минимальная зарплата НА РУКИ, ₸ в месяц. Вакансии без зарплаты показывать? 
6. Опыт (лет) и уровень (junior / middle / senior / lead)
7. Что исключить (технологии, отрасли, компании, слова в названии)?
8. Казахский язык: не владею / базовый / разговорный / свободно
9. Английский: A1–C2
10. Гражданство РК есть? (если нет — буду помечать вакансии «только для граждан РК»)
11. Удалёнку на российские компании рассматриваете? (по умолчанию исключаю «только РФ»)
12. Резюме: загрузите PDF, ссылку на hh.kz или вставьте текст
```

После ответа:
- Сохрани резюме в `resume.md`, выпиши из него навыки → `skills` в профиле.
- Собери `profile.json` по образцу `profile.example.json`:
  - `hh_sites` — по умолчанию два: hh.kz с городами пользователя (коды в `references/kz-specifics.md`:
    40 = вся РК, 160 = Алматы, 159 = Астана, 205 = Шымкент) и hh.ru с `work_formats: ["REMOTE"]` без `areas`
    (вся удалёнка СНГ). Если пользователь готов к переезду — добавь домены и страны из `hh_sites_relocation_examples`
  - `work_formats` — `REMOTE` / `HYBRID` / `ON_SITE`
  - `keywords` — обязательно и по-русски, и по-английски (международные площадки ищут по-английски)
  - `sources` — по умолчанию все из скрипта; группы, не подходящие профессии, убери
    (например, международную удалёнку при английском ниже B1)
  - `remote_allowed_regions` — откуда можно нанимать (по умолчанию worldwide/EMEA/Asia/CIS/Kazakhstan)
  - `career_pages` — компании, за которыми следить (см. `references/platforms.md`, раздел 5)
  - `title_must_match` — регулярка по названию из ключевых слов и синонимов (рус + англ)
  - `exclude_title` / `exclude_text` — регулярки исключений; осторожно с короткими словами, используй `\b`
  - `kazakh_level`: `none` / `a2` / `b1` / `c1`; `english_level`: `a1`…`c2`
  - `is_foreigner`: true, если нет гражданства РК
  - `tg_channels` — каналы из `references/platforms.md` (раздел 6): все казахстанские и общие IT,
    профильные (Python, техменеджмент, data) — только под профессию; группы (@cyprusithr) — в `tg_groups_browser_only`
- Покажи пользователю итоговый профиль коротким списком и попроси подтвердить.

## Фаза 2. Ежедневный прогон

1. **Проверка даты.** Если отчёт за сегодня уже есть в `reports/` — спроси, запускать ли снова.
2. **Резюме.** Если `resume.md` изменился с прошлого раза — обнови `skills` и отметь это в отчёте.
3. **Сбор скриптом** (путь к скрипту — относительно папки скилла):
   ```bash
   python3 scripts/kz_jobs.py search --profile ~/.kz-job-hunter/profile.json \
     --out ~/.kz-job-hunter/runs/$(date +%F).json --details
   ```
   `--details` подтягивает описания вакансий hh (точнее фильтры по тексту, языкам, тестовому).
   Источники скрипта: `hh` (hh.kz + hh.ru remote) · `enbek` · `tg` · `habr` · `getmatch` · `geekjob` ·
   `remoteok` · `himalayas` · `wwr` · `workingnomads` · `remotive` · `jobicy`. Ошибка одного источника не
   ломает прогон — она попадёт в журнал.
   Выводит счётчики и журнал по каждому источнику. Скрипт делает паузы 1–2 с между запросами — не убирай их.
4. **Браузерные источники** (только подтверждённые пользователем; подробности в `references/platforms.md`).
   Логинится пользователь сам. Порядок:
   - **LinkedIn — расширенный поиск** (раздел 7): Jobs за 3 дня → посты HR с #hiring/#вакансия/#openrole →
     вкладка Jobs на страницах компаний → поиск по фразам «ищем {kw}» / «we are hiring {kw}». Только прямые ссылки.
   - **Карьерные страницы** из `career_pages` (раздел 5).
   - **СНГ без API**: hirify.me (персональная лента), jobtoo.ru, talent-move.ru.
   - **Affiliate / ИИ**: ArbiHunter (после логина), aijobs.net (foorilla).
   - **Удалёнка без API**: Daily Remote, JustRemote, Jobgether; Wellfound / Indeed / Glassdoor — по желанию.
   - **Telegram-группы** из `tg_groups_browser_only` (@cyprusithr) — через web.telegram.org, сообщения
     с последнего прогона, ссылка `https://t.me/<группа>/<id>` обязательна.
   Найденное прогоняй через те же правила (полный текст, регион найма, флаги) и добавляй в отчёт с пометкой
   источника. Логин, капча или 403 → не обходить, отметить «нужен вход» и продолжить.
5. **Отчёт:**
   ```bash
   python3 scripts/kz_jobs.py report --in ~/.kz-job-hunter/runs/$(date +%F).json \
     --out ~/.kz-job-hunter/reports/$(date +%F).md
   ```
   Дополни отчёт браузерными находками и покажи пользователю (в чате таблицей или как документ/страницу,
   если такой инструмент есть). Перед показом выборочно открой 3–5 ссылок — убедись, что они живые.
6. **История.** После показа: `python3 scripts/kz_jobs.py mark-seen --in <run.json> --profile ~/.kz-job-hunter/profile.json`.

Что делает фильтр скрипта (`classify` в `kz_jobs.py`):
- отсев: уже видели · закрыта · название не по профилю · исключения по названию/тексту/компании ·
  «удалённо только по РФ / на территории РФ» · формат не тот · зарплата ниже порога
- зарплата сравнивается **на руки в тенге**: валюта по `rates`, gross × `net_ratio` (≈0.8); вакансии без зарплаты не отсеиваются
- флаги: нужен казахский · английский выше уровня · тестовое задание · только граждане РК (если `is_foreigner`)

## Фаза 3. Отклики (только по подтверждению)

1. Покажи список: «Готов откликнуться на N вакансий: … Отправляем?» — жди явного «да». Можно выбрать часть.
2. Для каждой вакансии напиши сопроводительное (ниже). Если вакансия с тестовым — не откликайся автоматически, вынеси в «вручную».
3. Отклик на hh.kz/enbek.kz — через браузер в сессии пользователя: открыть вакансию → «Откликнуться» → выбрать резюме → вставить письмо → отправить.
   - Пауза 5–10 с между откликами, после каждых 5 — 1 мин.
   - Капча или «слишком много откликов» → **сразу стоп**, остаток в «вручную».
   - Засчитывай отклик, только если площадка показала подтверждение.
4. Telegram-вакансии: не пиши HR от имени пользователя без отдельного подтверждения на каждый текст; по умолчанию — подготовь текст и дай ссылку.
5. Запиши результат в `applied.json`.

### Сопроводительное письмо

5 частей, 6–9 предложений, на языке вакансии:
1. **Приветствие** — «Добрый день, команда {Компания}!» / «Сәлеметсіз бе, {Компания} командасы!» / «Hello {Company} team!» (если указано имя рекрутера — по имени).
2. **Кто я** — одна фраза: роль + опыт + домен, конкретно под вакансию.
3. **Релевантный опыт** — 2–3 факта из резюме, совпадающих с требованиями (цифры, продукты, стек).
4. **Сопоставление** — прямо сошлись на 2–3 требования вакансии: «Вы ищете X — я делал(а) X в Y».
5. **Закрытие** — готовность обсудить, удобный формат связи.

Запрещено: зарплата, пересказ резюме, извинения за пробелы, выдуманные факты (всё проверяемо по `resume.md`).

## Фаза 4. Обновление резюме

По фразам «обнови резюме», новый PDF, ссылка на hh.kz: прочитай, покажи что изменилось, обнови `resume.md` и `skills`.

## Фаза 5. Расширение источников (раз в неделю или по просьбе)

- Проверь активность `tg_channels`: в журнале скрипта есть дата последнего поста; канал без постов > 30 дней — предложи убрать.
  Каналы с 0 подходящих 4 недели подряд — предложи убрать из профиля (но не удаляй сам).
- Найди новые каналы: веб-поиск «вакансии {профессия} Казахстан telegram», tgstat.ru (категория «Работа», страна KZ).
  Проверка: `https://t.me/s/<канал>` открывается, пост ≤ 7 дней, есть вакансии, а не курсы/реклама.
- Веб-поиск новых площадок: «{профессия} вакансии Казахстан {год}», «{profession} jobs Kazakhstan remote».
- Новое — предложи пользователю, в профиль добавляй после согласия. В отчёте: «Источники: +N, −N».

## Принципы

- Не останавливаться на одной ошибке; всё фиксировать в журнале отчёта.
- Не выдумывать данные о компании или пользователе.
- Не обходить капчи и антибот-защиту; не ускорять скрипт, убирая паузы.
- Ничего не отправлять на адреса, кроме самих площадок.
